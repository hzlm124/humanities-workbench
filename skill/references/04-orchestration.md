# 04 · 两级编排（DSH 原生）

Misaka 的卡死来自三处：把整套契约注入每个请求、每个角色再起一个 harness、节点递归等待彼此的会话。
这套编排只保留它的**分工与审查结构**，把执行换成本机已有的 subagent / 文件 / 团队任务。

## 角色

| 角色 | 谁 | 职责 | 禁止 |
|---|---|---|---|
| 主控（Plan Seat） | 主 agent | 框定、切卡、分派、综合、处置、决策、交付 | 不亲自做完所有检索；不在结论阶段才想起证据 |
| 研究员（Sister） | 每个 subsagent | 一张卡：检索、读原件、产出 findings + 来源 | 不替主控写结论；不越界改别人的文件 |
| 红队 | 独立 subagent（新上下文） | 只挑错：前提、事实、最强竞争解释、沉默处 | 不扩写、不润色、不合并观点 |
| 分歧审查 | 另一个独立 subagent | 提未取之路与缺口 | 不重复红队的纠错工作 |
| 用户 | — | 定问题、定价值、批计划 | — |

**红队与分歧审查不得与主控共享上下文。** 同一个上下文自审，等于没审。

## 工作目录（一个研究一个目录）

```
research/<slug>/
  00-plan.md              计划：断言清单、覆盖表、卡片切分
  01-cards/C01.md ...     卡片（派工单）
  02-findings/C01.md ...  研究员交付（findings + 来源）
  03-conclusion/v1.md ... 结论各版本（不覆盖旧版）
  04-red-team/R1.md       红队意见（issues 列表）
  05-dispose.md           逐条处置记录
  06-divergence/D1.md     未取之路 + 缺口
  07-decide.md            决策：开哪几条线、拒绝哪条及理由
  08-final/report.md      交付稿
  sources/                下载的原件（原名 + 日期前缀）
  sources.jsonl           来源账本（每行一条 source）
  gaps.md                 未解决缺口（跨阶段累积）
```

**文件是唯一的交接介质。** 不用长消息传递研究内容：subagent 写文件，主控读文件。

## 阶段 0 · 框定（主控自己做）

1. 复述问题，并写出它**还可能意味着什么**（2–4 种读法），指出哪种读法下答案会不同。
2. 列**断言清单**：把问题拆成 5–15 条可判真伪的具体命题。这是后续一切工作的骨架。
3. 做**覆盖表**（见 `09-coverage.md`）：子问题 × 行动者 × 时期 × 维度 → 卡片编号；空格显式写 `gap`。
4. 切卡。规则：
   - 一张卡 = 一个单元（一个行动者/地区/时期/维度/一类材料）。
   - 一张卡 = 一个 subagent 一轮能跑完（建议 ≤ 12 次工具调用、≤ 3 个来源族）。
   - 定义、标准、基线放 `00-plan.md` 共享，不重复进每张卡。
   - 卡数由问题结构决定，不由并行度决定。
5. 写 `00-plan.md`：断言清单、覆盖表、卡片清单、**停止条件**（什么情况下算查够了）、**证伪条件**。
6. 若涉及用户的价值判断或设定取舍，先把选择题抛给用户（不等答案就往下跑，是这类工作最常见的浪费）。

## 阶段 1 · 分派（并行）

卡片模板字段（缺一不可）：

```yaml
id: C03
question: <一句可答的具体问题>
why: <它支撑哪条断言 / 覆盖表哪一格>
method: <史料批判 / 统计比对 / 概念史 / 口述 / 反事实约束检验>
sources: <先用哪几个库/全宗；列出 2-4 个具体库与检索式>
falsifiers: <什么材料出现会推翻工作假设>
deliverable: 02-findings/C03.md
write_scope: 02-findings/C03.md, sources/C03-*
limits: <最多轮次；不可得时如何降级>
```

派工消息（给 subagent）里只放：**角色一句话 + 卡片全文 + 交付格式 + 写入范围 + 「读 SKILL 的哪一册」**。
不要把整套方法论贴进 prompt；让 subagent 自己 `skill` 加载本技能并按需读 references。

并行度：独立卡一次发 2–4 个；有依赖的卡按依赖顺序。超过 4 张卡且互相独立时，改用团队任务（`team_task_create`）登记，
把写入范围写进 `write_scopes`，避免两个研究员写同一个文件。

## 阶段 2 · 综合（主控做）

1. 先读 `02-findings/*.md` 全文，不看摘要。
2. 做三件连线：概念是否对齐（同一个词在两卡里是否同义）、是否共享未检验前提、独立根据 vs 重复引用。
3. 写 `03-conclusion/v1.md`，固定分栏：

```
## 直接回答
## 共同发现（各卡一致）
## 竞争发现（各卡不一致，写明分歧起点）
## 关键证据（带定位符）
## 反证与不利材料
## 方法局限
## 价值前提（normative，显式标出）
## 未决问题与缺口
## 什么新证据会改变这个判断
```

纪律：不投票，不用「多数研究认为」压掉少数读法；证据不足就写证据不足；结论可以是「问题需要重新表述」。

## 阶段 3 · 红队（独立 subagent）

派工内容：结论文件路径、计划文件路径、来源账本路径、`05-red-team.md` 输出路径、issues 格式。
红队**不得**读主控的对话上下文（新 subagent 天然满足）。

issues 格式（每条）：

```
kind: premise | fact | inference | concept | method | omission | normative
question: <这条批评在问什么>
rationale: <为什么这条影响结论，影响多大>
check: <解决它需要什么具体核查（查哪份材料、核对哪个数字）>
priority: high | medium | low
material: true | false
```

`material: true` 的问题必须被处置；`false` 的只记录。

## 阶段 4 · 处置（主控做，逐条）

写 `05-dispose.md`，每条 material 问题**恰好一个**处置：

| 处置 | 含义 | 后续 |
|---|---|---|
| revise | 本节点重做（补卡或改写结论） | 产生 v2，红队复审 |
| rebut | 不成立，写明为何 | 红队复审时读理由 |
| concede | 立场成立但付此代价 | 最终稿列出「本答案接受的代价」 |
| covered | 另一条线/另一张卡已有 | 指明编号，并说明它如何回答 |
| park | 留给终审 | 进 `gaps.md` |
| branch | 暴露真正不同的前提（不是错误） | 交阶段 5 决策 |

规则：**原则性分歧只能 rebut 或 concede，不能 revise；事实错误只能 revise。**
复审只看修订是否解决了原问题、反驳是否成立、修订本身引入了什么；已 concede/covered/park 的不得重复提，除非新版本改动了它。

## 阶段 5 · 分歧审查（新上下文 subagent）

派工：结论路径、计划路径、`gaps.md`、输出路径。要求两类产出：

1. **未取之路**：结论放弃了什么、从未选择什么——别的假设/方法/框架/意识形态/视角/情景/读法/材料族/分解方式，以及对问题本身的批判（谱系学、症候阅读、意识形态批判）。
2. **缺口**：任何回答这个问题都必须补、而结论没补的东西（某类材料、某个行动者、某段时期、某种语言）。标 `gap: true`。

每条提案必须写：前提是什么、它可能改变答案的哪一处、验证它需要什么研究。
**缺口回本节点补；未取之路进决策。** 不要为凑数制造对立；结论本线能吸收的「另一种材料」是缺口，不是另一条路。

## 阶段 6 · 决策与交付

1. 写 `07-decide.md`：每条未取之路 → 开（新目录/新子任务）或拒（写明理由：另一条线已覆盖 / 与本问题无关 / 资源不许可）。
   「不值得」不是理由；「与本问题范围无关」是理由，但要写清范围。
2. 交付按 `10-deliverables.md`。正文不出现流程词（节点、卡片、红队、处置、v2）。
3. 更新 `sources.jsonl`，跑一遍 `scripts/check_ledger.py` 校验。

## 上下文纪律（防卡死的具体条款）

- 每个 subagent 的 prompt ≤ 1500 字，其余靠文件与技能分册。
- 单个 subagent 最多 12 次工具调用、3 次重试；超限就交付已有部分并标 `incomplete`。
- 主控不在同一轮里同时做：切卡、派工、写结论。一轮做一件事。
- 长任务用 `todo_write` 记阶段进度；阶段切换时把结论摘要（≤ 15 行）写进 `00-plan.md` 尾部，供中断恢复。
- 任何一步超过约 10 分钟无产出，停下来报告卡在哪，不要静默重试。

## 中断恢复

重开一轮时只读三个文件：`00-plan.md`（含尾部摘要）、`gaps.md`、最新 `03-conclusion/v*.md`。
不要重读全部 findings——除非某条断言需要重新核。
